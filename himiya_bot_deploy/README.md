# 🧪 Химия — бот знакомств «после Дайвинчика»

Знакомства, где сначала смысл, а потом фото. Свайпы привычные — но анкета говорит больше,
чем селфи, а после мэтча включается «Ледокол»: 5 вопросов, и только потом контакты.

**Что внутри папки**

| Файл / папка | Что делает |
|---|---|
| `prototype.html` | Интерактивный макет бота — можно потыкать весь путь целиком (регистрация → мэтч → Ледокол → чат) |
| `bot.py` | Точка входа, запуск polling + воркер сгорания мэтчей |
| `handlers/` | Логика: `start`, `registration`, `feed`, `match` (Ледокол), `chat`, `profile`, `admin` |
| `services/matchmaking.py` | Формула «химии», тексты карточек, чек-лист заполненности анкеты |
| `db.py` | Вся работа с SQLite (схема + запросы) |
| `texts.py` | Все тексты и вопросы в одном месте — меняешь «голос» продукта без правки кода |
| `handlers/demo.py` | Демо-анкеты с автоответами — тест полного цикла в одиночку (`/demo`) |
| `tools/brand.py` | Брендинг бота через Bot API: имя, описания, команды, меню |
| `tools/preview.py` | Генерирует `preview_design.html` из боевых текстов |
| `Dockerfile`, `docker-compose.yml`, `deploy/` | Готовый деплой на VPS |
| `keyboards.py` | Клавиатуры |
| `tests/test_flow.py` | Автотест ядра: мэтч → квест → разблокировка → сгорание. Без токена и сети |
| `tests/test_news.py` | Автотест ленты: RSS/Atom, дедуп, ранжирование, шаринг, «вы оба читали» |
| `services/news.py`, `services/ingest.py` | Темы, парсинг фидов, ранжирование, фоновая загрузка |
| `handlers/news.py` | Карточки ленты, шаринг в чат, реакции, дайджест |
| `.env.example` | Шаблон конфига |

## Фишка №1 — «Слепая» анкета, которая говорит больше фото

- 5 нестандартных вопросов (не «люблю путешествия», а «идеальная пятница — это…»).
- **Голосовое 15–30 сек** — главный анти-бот: скриптом не подделать, зато сразу слышно живого человека.
- **Фото скрыто** в ленте и открывается только после взаимного мэтча (или за ⭐, если очень надо).
- «Химия XX%» считается по совпадению ответов (70%) и общих интересов (30%) — а не по лайкам.

## Фишка №2 — «Ледокол»: мэтч ещё не значит чат

Главная боль Дайвинчика — мэтчи, которые умирают через 3 секунды: «привет», «привет», тишина.

- После взаимного лайка открывается квест из 5 вопросов: «Какой отпуск выберем?», «Кто первым извинится после ссоры?»
- Отвечают **оба**, ответы раскрываются **синхронно** — только когда ответили двое. Никто не подглядывает.
- Только после 5 вопросов открываются контакты и анонимный чат.
- Итог: к моменту первого сообщения у пары уже есть 5 общих тем и понятная совместимость.

## Фишка №3 — Мэтчи сгорают за 48 часов

Нет сообщений в течение `MATCH_TTL_HOURS` → мэтч закрывается, оба получают уведомление.
Это не жестокость, это гигиена: лента не превращается в кладбище чатов, а «мэтчи» снова
означают «кто-то действительно хочет поговорить».

## Фишка №5 — 📰 Лента: контент как топливо для разговора

Не новостник. Главная проблема дейтинга — не «мало людей», а **не о чем говорить после «привет»**.
Поэтому:

- **Темы берутся из анкеты** (кино, музыка, спорт, психология, Лондон…) — человек не заполняет ещё одну форму.
- **Только русский язык и только добрый контент.** 12 живых RSS/Atom российских изданий:
  The Art Newspaper Russia, «О театре», InterMedia, «Мир фантастики», «Кинорепортёр»,
  N + 1, «Наука и жизнь», Sport24, 34travel, «Гастрономъ», AdMe, «Афиша Daily».
- **Темы:** 🎨 Искусство · 🩰 Театр и танцы · 🎧 Музыка · 🎬 Кино · 🔬 Наука · ⚽ Спорт ·
  ✈️ Путешествия · 🍳 Еда · 😊 Милые истории · 🎉 Культура и город.
- **Фильтр негатива на входе** (`services/news.py`): войны, политика, криминал, смерти,
  скандалы, болезни и деньги отсекаются **до записи в базу**, а не в выдаче. Плюс надбавка
  к рангу за «добрые» слова (фестиваль, выставка, рецепт, танец, красота…).
- **Порция, а не поток:** 3–5 материалов в день (`☕ Дайджест`) вместо бесконечного скролла. Свежесть + популярность + дедуп похожих заголовков.
- **Кнопка №1 на карточке — «💌 Поделиться с мэтчем»**, а не «Открыть». Карточка приходит партнёру прямо в анонимный чат.
- **Реакции внутри чата:** «🔥 Класс / 🤔 Спорно / 💬 Обсудить» — реакция приходит второму человеку как обычное сообщение, разговор завязывается без выхода из бота.
- **«👀 Вы оба это читали»** — если оба сохранили одну статью, бот сам находит общий материал и предлагает написать. Это лучший повод для первого сообщения, который вообще можно придумать.
- 🔖 Закладки, ⚙️ `/topics`, жалоба на материал — на месте.

**Технически:** `services/news.py` (темы, парсинг RSS 2.0 + Atom, фильтр негатива, ранжирование, дедуп),
`services/ingest.py` (фоновая загрузка каждые 30 мин + авто-чистка при смене контент-набора),
`handlers/news.py` (карточки, шаринг, реакции, дайджест), воркеры `ingest_worker` и `digest_worker` в `bot.py`.

**Контент-политика:** `NEWS_VERSION` в `services/news.py`. Меняешь список изданий или темы →
поднимаешь версию на 1 → при следующем старте старые статьи и источники вычищаются целиком,
лента засеивается заново. Случайно иностранный или «военный» контент в ленту не вернётся.

**Тесты:** `python tests/test_news.py` (офлайн-фикстуры RSS/Atom, дедуп, ранжирование, шаринг, «оба читали») и `NET=1 python tests/test_news.py` + живой фид BBC.

> Важная граница: лента должна оставаться **поводом для разговора, а не заменой ему**. Поэтому нет бесконечной ленты, нет автоплея и нет счётчика «сколько ты не читал». Есть порция в день и большая кнопка «поделиться».

## 🧯 Если команды «не работают»

Диагностика по шагам (именно это случилось на первом запуске):

1. **Два экземпляра бота одновременно.** Telegram отдаёт апдейты только одному поллеру,
   второй получает `Conflict: terminated by other getUpdates request` — команды теряются.
   Проверка: `ps aux | grep "[b]ot[.]py"` — должен быть **ровно один** процесс.
   Защита: `bot.py` держит `fcntl`-блокировку на `logs/bot.lock`, второй запуск выходит с ошибкой.
2. **Процесс умер или заморожен** → апдейты копятся в очереди Telegram.
   Проверка: `pending_update_count` в `getWebhookInfo` растёт, а `logs/bot.log` молчит.
3. **Состояние анкеты терялось при рестарте** (было `MemoryStorage`). Теперь FSM в SQLite
   (`storage.py`, таблица `fsm`) — человек продолжает с того же места.
4. **`/ping`** (для админа) — heartbeat процесса, число пользователей/статей/мэтчей.
5. Все апдейты пишутся в `logs/bot.log` строкой `⬇️ message <id> (@ник): /start` —
   сразу видно, доходят ли они до бота.

```bash
pkill -f "python3 -u [b]ot.py"; rm -f logs/bot.lock   # зачистить всё
python3 -u bot.py                                      # запустить один
tail -f logs/bot.log                                   # смотреть, что приходит
```

## Деплой на 24/7

**Docker (проще всего):**
```bash
cp .env.example .env      # вставь BOT_TOKEN и ADMIN_IDS
docker compose up -d --build
docker compose logs -f
```

**VPS без Docker:**
```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
cp .env.example .env
sudo cp deploy/himiya-bot.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now himiya-bot
```

База — SQLite в `DB_PATH`. При переходе на несколько тысяч пользователей меняется на
PostgreSQL (все запросы уже изолированы в `db.py`).

## Что делать дальше (по приоритету)

1. **Деплой**: сервер (любой VPS), `systemd`-юнит или Docker, `PostgreSQL` вместо SQLite при росте.
2. **Кнопка «Пожаловаться» → автобан** после 3 жалоб + очередь на ручную модерацию фото.
3. **Репутация после встречи**: обе стороны отмечают «пришёл / не пришёл / крип» — это главный
   дифференциатор, которого нет ни у кого из конкурентов.
4. **Умный подбор**: приоритет по часовому поясу, активности и «взаимной химии» (сейчас — по городу).
5. **Анти-фейк на входе**: обязательное голосовое + проверка, что на фото есть лицо.
6. **Аналитика**: воронка `start → анкета → первый мэтч → первый чат → первый ответ` — по ней
   видно, где отваливаются люди.
7. **Приглашения**: реферальная ссылка «приведи друга — +1 буст».

## Как лента усиливает дейтинг (а не размывает его)

- **DAU.** Дейтинг открывают раз в неделю, ленту — каждый день. Лента даёт ежедневный повод вернуться, а значит больше мэтчей без затрат на трафик.
- **Конверсия в первое сообщение.** Это главная метрика продукта: шаринг карточки снижает порог «что написать» почти до нуля.
- **Retention после мэтча.** Пары, которые обмениваются карточками, не сгорают — сгорают те, у кого нет темы.
- **Тёплый старт для рекламы.** 1 нативная карточка в дайджесте — но только по темам, которые человек выбрал сам, и с пометкой.

## Метрики, на которые смотреть с первого дня

- D1/D7 retention (вернулся ли человек завтра);
- доля анкет, дошедших до мэтча;
- **доля мэтчей, где случилось первое сообщение** — это и есть метрика, за которую борется Ледокол;
- доля сгоревших мэтчей (норма 20–35%);
- жалобы на 1000 сообщений;
- **доля мэтчей, где был шаринг карточки** и сколько из них дошли до живого диалога.

## Технические заметки

- aiogram 3.31, FSM на `MemoryStorage` (для продакшена — `RedisStorage`, чтобы состояния не терялись при рестарте).
- SQLite через `aiosqlite`; схема создаётся автоматически при старте.
- Чат между людьми — релей через бота: сообщение хранится в таблице `messages`, ответ ищется
  по `reply_to_message` → работает и кнопкой «↩️ Ответить», и обычным Reply.
- Воркер `expiry_worker` раз в 15 минут закрывает мэтчи без сообщений.
