# 🚀 Деплой «Химии» на bothost через GitHub

Пошагово, без «догадайся сам». Всё, что нужно — аккаунт bothost, твой репозиторий
`rayfovishsaid-spec/my-ad-bot` и токен бота.

---

## ⚠️ Прочитать до начала (3 важных пункта)

1. **Бери тариф Basic (99 ₽), а не бесплатный Starter.**
   На Starter, судя по их же описанию, **данные стираются при перезапуске** и нет
   env-переменных. Для бота знакомств это смертельно: обнулятся анкеты, мэтчи и чаты
   при каждом рестарте. На Basic есть **постоянный диск (Volume)** и переменные окружения.
2. **Один экземпляр бота на один токен.** Если бот одновременно запущен в двух местах,
   Telegram отдаёт апдейты то одному, то другому, и в логах появляется
   `Conflict: terminated by other getUpdates request`. Копию в песочнице я остановлю —
   больше нигде бота с этим токеном не запускай.
3. **Токен — только в переменных окружения bothost.** Ни в коде, ни в README, ни в коммитах.

## Шаг 1. Почистить репозиторий

Сейчас в репозитории лежит папка `workspace-01a1c222-…` — для хостинга это плохо:
ему нужен проект **в корне** репозитория.

### Вариант А — через сайт GitHub (без консоли)

1. Открой `https://github.com/rayfovishsaid-spec/my-ad-bot`
2. Удали папку `workspace-01a1c222-…` (открыть папку → значок «…» → Delete directory → Commit)
3. **Add file → Upload files** → перетащи **содержимое** архива `himiya_bot_deploy.zip`
   (не саму папку, а файлы внутри: `bot.py`, `main.py`, `handlers/`, `services/` и т.д.)
4. Commit changes

### Вариант Б — через git в консоли (надёжнее)

```bash
git clone https://github.com/rayfovishsaid-spec/my-ad-bot.git
cd my-ad-bot
rm -rf workspace-*            # убрать старую папку
# распакуй сюда himiya_bot_deploy.zip (файлы должны лежать в корне)
git add -A
git commit -m "Химия: бот знакомств (анкеты, Ледокол, лента)"
git push
```

**Проверь результат:** в корне репозитория должны быть
`bot.py`, `main.py`, `requirements.txt`, `Dockerfile`, `db.py`, `texts.py`,
папки `handlers/`, `services/`, `deploy/`, `assets/`, `tools/`.

**Чего в репозитории быть НЕ должно:** `.env`, `himiya.db`, `logs/` — они уже
исключены в `.gitignore`. Если загружаешь через веб — просто не тащи их из архива
(в архиве их нет).

## Шаг 2. Создать бота в bothost

1. Зайди в [dashboard](https://bothost.ru/dashboard.php) → **Создать бота / New project**
2. Платформа: **Telegram**
3. Язык: **Python** (или сразу «Docker» — см. ниже)
4. Способ загрузки кода: **GitHub** → авторизуй bothost в GitHub →
   выбери репозиторий `my-ad-bot`, ветку **main**
5. Способ запуска:
   - **Рекомендую: «Dockerfile»** — в проекте уже лежит `Dockerfile`, среда соберётся
     предсказуемо (Python 3.12 + зависимости).
   - Либо «Python» и команда запуска: `python main.py`

Если платформа спрашивает «файл запуска» — укажи **`main.py`** (он есть специально
для таких хостингов и вызывает `bot.py`).

Установка зависимостей: `pip install -r requirements.txt` — bothost делает это сам,
если видит `requirements.txt` (он в корне).

## Шаг 3. Переменные окружения (обязательно)

В панели бота → **Environment / Env variables** → добавь:

| Переменная | Значение | Зачем |
|---|---|---|
| `BOT_TOKEN` | токен из @BotFather | без него бот не стартует |
| `ADMIN_IDS` | `7697964856` | твой ID — доступ к `/admin`, `/demo` |
| `DB_PATH` | `/data/himiya.db` | база на постоянном диске |
| `MATCH_TTL_HOURS` | `48` | через сколько мэтч сгорает |
| `DAILY_LIKES` | `40` | лимит лайков в сутки |
| `INGEST_MINUTES` | `30` | как часто тянуть RSS |
| `DIGEST_HOUR` | `10` | во сколько слать утренний дайджест |
| `DIGEST_TZ_OFFSET` | `3` | часовой пояс Ставрополя (UTC+3) |

## Шаг 4. Постоянный диск (Volume) — иначе база обнулится

В панели бота → **Volumes / Диски** → добавь диск и смонтируй в **`/data`**.

Именно поэтому `DB_PATH=/data/himiya.db`: всё, что бот запомнил (анкеты, мэтчи,
темы ленты, закладки), останется после рестарта и обновлений.

Проверить, что сработало: после перезапуска бот должен помнить твою анкету —
`/profile`.

---

## Шаг 5. Первый деплой и проверка

1. Жми **Deploy / Запустить**
2. Открой **логи**. Правильный старт выглядит так:

```
🧪 Химия запущена
Start polling
Run polling for bot @chemistry7LOVE_bot id=… - 'Химия · знакомства'
Лента: +125 новых статей
```

3. В Telegram: `/start` → анкета → `/ping`

`/ping` — твоя диагностика: показывает heartbeat, число пользователей, статей, мэтчей.
Если heartbeat «свежий» (несколько секунд) — процесс живой.

4. `/demo` — три демо-анкеты с автоответами, чтобы прогнать весь путь в одиночку.
   Убрать: `/demo_off`.

5. Аватар: @BotFather → `/setuserpic` → загрузи `assets/logo.png`.

bothost сам пересоберёт и перезапустит бота. База на volume не пострадает.

## 🧯 Если что-то не так

| Симптом в логах / поведении | Причина | Что делать |
|---|---|---|
| `Conflict: terminated by other getUpdates request` | запущено **два** бота с одним токеном | останови лишний экземпляр (в песочнице, локально, у знакомого) |
| `❌ Нет BOT_TOKEN` | переменная не задана или не применилась | добавь `BOT_TOKEN` в Env и перезапусти |
| Логи пустые, бот молчит | неверная команда/файл запуска | укажи `main.py` или используй Dockerfile |
| После рестарта пропали анкеты | нет Volume или `DB_PATH` не на `/data` | смонтируй диск, проверь `DB_PATH` |
| `ModuleNotFoundError: aiogram` | зависимости не установились | проверь, что `requirements.txt` в корне, пересобери |
| Бот отвечает через раз, кнопки «висят» | старая версия кода без фиксов | сделай `git push` и дождись пересборки |
| `/ping` показывает старый heartbeat | процесс завис | перезапуск в панели; если повторяется — напиши в поддержку bothost про лимиты CPU/RAM |

Полные логи у бота есть и внутри контейнера: `logs/bot.log`.

## 🔐 Безопасность токена

Токен уже засветился в переписке. После того как всё заработает:

1. @BotFather → `/mybots` → твой бот → **API Token** → `/revoke`
2. Получи новый токен
3. Замени `BOT_TOKEN` в панели bothost → перезапусти бота
4. Никогда не коммить `.env` и не вставляй токен в код

## Что уже готово в проекте под хостинг

- `main.py` — точка входа для платформ, которым нужен `main.py`
- `Dockerfile` + `docker-compose.yml` — контейнерная сборка
- `requirements.txt` — зависимости (`aiogram`, `aiosqlite`)
- `deploy/himiya-bot.service` — если однажды переедешь на обычный VPS
- `.gitignore` — `.env`, базы и логи не попадут в репозиторий
- `DB_PATH` через переменную окружения — база не привязана к папке проекта
- Защита от двойного запуска (`logs/bot.lock`) — второй экземпляр просто не стартует
- Watchdog + супервизор (`run.sh`) — если процесс завис, его перезапустят
